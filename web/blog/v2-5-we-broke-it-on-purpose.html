RELEASE · CLI v2.5 · PROTOCOL v2.5

We broke it on purpose.

July 31, 2026 · reHuman Labs

agentchute v2.5 is not compatible with v2. Message filenames changed, so an old binary and a new one can't read each other's mail. Upgrade every agent in a pool at once. Here's what changed, and the message that convinced us to change it.

The message

We stopped using our own agents for about three weeks. Life happened; the panes got closed.

When we came back, one agent had a message waiting that had been sitting unread for twenty-three days. A code review someone had asked for, answered, and then never seen.

Nothing was broken. The message was delivered exactly as designed — written to the right inbox, on disk, intact, waiting. That was the problem. We had built a mailbox that accepted letters for people who had moved out, and never mentioned it to anyone. The sender got no error. The system had no idea. It couldn't tell the difference between an agent thinking hard and an agent that no longer existed.

You can call that best-effort delivery and be technically right. We'd rather it just say so.

What changed

Agents expire. A registration now lasts about an hour unless the agent keeps saying it's there. Any agent doing ordinary work quietly clears out the ones that stopped. No daemon, no watchdog, no human — the cleanup rides along with work that was happening anyway.

Sending to someone who isn't there fails, out loud. Immediately, at the moment you send, while you can still do something about it. Not silently, into a mailbox nobody will open.

Message names are timestamps. They used to be per-conversation counters, and a counter is shared state that exactly one writer may touch — which dragged in locks, fences, crash recovery, and a page of documentation warning you about the sharp edges. All of it defended an exact ordering that nothing ever read. Timestamps need none of it. That deletion is most of the six thousand lines this release removes.

Old mail still reads. Every message already in your inboxes stays readable. Only new ones use the new names.

The promise we broke

At 1.0 we wrote that the identity grammar would only ever change through a deprecation process, and that the wire wouldn't break under you. We changed it directly instead.

We could have called this v3 and technically kept our word. We didn't, because the honest description of what happened is: we found something wrong with the design, the fix was worth more than the promise, and the promise was ours to keep or account for. So this is us accounting for it — in the release notes, on the front page, and here.

It ships as 2.5 rather than 3.0 because the primitives, the envelope and the lifecycle guarantees are all unchanged. One thing broke. We'd rather name that precisely than round it up.

One more honest thing

Delivery is now stated as at-most-once: we hand the message over, and that's the whole promise. It was never actually more than that — a few places in the old code and spec implied otherwise, and we removed those claims instead of pretending to honor them. What you get is what the code does.

Upgrading

Run agentchute update once. It stops the old supervisors for you, then relaunch each lane. Don't run half a pool on each version — they can't read each other. The cutover guide has the exact sequence, including how to confirm the old processes actually stopped, and how to roll back if you need to.

agentchute is a protocol and a faithful reference implementation, not a product. No support tier, no SLA. Build on it — and when we break something, you'll hear it from us first.
