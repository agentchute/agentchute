# agentchute v2.5 — implementation plan

Status: REVISION 2.5 — draft verified by two independent passes (repo-fidelity + decision-fidelity, ten findings folded), then team review: grok (three defects folded; APPROVED rev 2.1), sonnet (one dead-code defect + two pin-downs folded; APPROVED rev 2.2), codex (five update/release defects folded as 2.3; four propagation/under-specification catches folded as 2.4 — A7/A8 composite propagation, spool retry preserving ask/reply flags, one decided release workflow, two-sample fencing verification — with A7/A8, C28, §3 confirmed correct; final installer-coverage mis-fold folded here as 2.5). Ledger in §5.

Source of truth: `docs/decisions/agentchute-v2.5-proposal.md` (rev 2.3). This plan turns that decision record into ordered, PR-sized slices. Every value the record left open is fixed in the constants table below; slices cite exact files/functions from the current tree. An implementer picks one slice and needs nothing else.

**Installation & update coverage** (explicit, per owner requirement): the install/update surface is carried by A8 (hook templates + enrollment marker + doctor hook-sanity — all //go:embed'd, so template edits are binary changes), B2 (the `agentchute update` self-update flow becomes the wire-break forcing function via lease invalidation; setup reset loses registration-clearing), B10 (release pipeline: goreleaser, release.yaml's pinned-Go preflight vs ci.yaml's floating `stable`, install smoke from the built asset, provenance `vcs.modified=false`), and §3 (the live-pool cutover: what update does step by step, mixed-version honesty, rollback stance). The `ac` dispatcher shims are deliberately untouched — no slice changes their behavior. `install.sh` gets exactly one change: a test-only `AGENTCHUTE_BASE_URL` override (B10), which is what lets the release smoke run the REAL installer against the exact pre-publish archive instead of merely claiming installer coverage.

Conventions used throughout:
- "loop" = the pool directory (`<loop>` = e.g. `.agentchute/loop`). Path helpers live in `internal/loop/config.go`.
- "own lock" / "recipient lock" = `loop.WithAgentLock` (`internal/loop/filelock_unix.go:36-70`), the per-agent flock on `<loop>/state/<id>/.lock`. It is NON-REENTRANT (same-process second acquire deadlocks, 5s timeout) and `ensurePrivateDir` creates `<loop>/state/<id>/` before locking.
- All new state files are written with `atomicWriteFile` (`internal/loop/registration.go:501-549`) unless stated otherwise.
- Local test runs must strip `AGENTCHUTE_*` env (`env -u ...`) — go test under a live runner leaks `AGENTCHUTE_SERVE_TOKEN`/`LOOP_DIR` and produces false "serve lease fenced" failures. CI is authoritative.
- The working checkout is the LIVE fleet bus. Never point tests at the real `.agentchute/loop/`; use `t.TempDir()` fixtures.

#### A2 — runner: delete the one-shot seen set; interval re-cue + startup cue
**Goal.** The runner cues whenever unread mail sits in the inbox — including mail present at startup — retrying every 60s, only through the idle window. Deletes `seenInboxFiles`.
**Depends on.** none.
**Changes** (all in `internal/cli/serve.go` unless noted):
- Delete field `seenInboxFiles` (line 222), its init (:403), and the delta logic in `pollOnce` (:562-593). Delete the `enqueueNew bool` parameter of `pollOnce` and the seeding-poll distinction (`pollLoop` :528-541 calls the same `pollOnce()` before the ticker and per tick).
- New cue predicate in `pollOnce` (C16): after lease renew + heartbeat, `if hasPendingInboxMail() && (rt.lastInjectionIsZero() || now-lastInjection >= recueInterval) { enqueueWake(recue: !lastInjectionIsZero-for-this-pending-period) }`. Track "pending period": store `lastInjection` as today (runner.json `LastInjection`, `serve.go:847-866`); a period starts when `hasPendingInboxMail` transitions false→true (one new bool field `wasPending` on `runnerRuntime`); the FIRST wake of a period is `recue=false`, later ones `recue=true`.
- `enqueueWake(recue bool)` (:602-614): `wakeCh` becomes `chan bool` cap 1; keep the non-blocking coalesce; a queued `false` is never downgraded to `true` (if send fails because full, leave as-is).
- `waitForInjectionWindow(recue bool)` (:655-684): when `recue`, use after-idle behavior unconditionally (skip both Ctrl-C branches). First-cue behavior per `--interrupt-policy` unchanged.
- `injectLoop` (:616-627): pass the received recue flag through.
- `injectIfPending` (:629-640): when the re-check finds the inbox drained, CLEAR `pendingWake` (and saveState) instead of leaving it true forever.
- `hasPendingInboxMail` (:642-653): unchanged — skipped/malformed names still count, fail-open on list error stays.

## 3. MIGRATION + RELEASE CHECKLIST (live pool cutover)

Preconditions: all Group B slices merged to the release branch; Group A already live on the pool (it is wire-compatible and de-risks the break).

1. **Freeze sends.** Announce on the bus; agents finish in-flight turns. (Soft step — the mechanism below tolerates stragglers.)
2. **Run `agentchute update` once** (any lane, or operator shell) — **NEVER with `--no-resync` for this upgrade** (the old updater's no-resync path exits without executing the new binary, so nothing would ever fence — codex catch). What actually happens on this FIRST upgrade: the OLD update.go swaps the binary, then re-execs the NEW binary's setup, whose reset step runs `InvalidateAllServeLeases` (the current enrollment marker and `--stale-after` are replayed). Registrations are NOT cleared. The in-process invalidate-right-after-swap behavior described in B2 exists only from v2.5 onward.
3. **Every running old-binary supervisor fences out** on its next poll tick — but only AFTER the new binary's setup reaches its reset step. **Verify with two samples, not one** (codex catch, sharpened rev 2.4: registrations are preserved, so immediately after a CORRECT fence an old-protocol row still exists and is recently fresh — one snapshot cannot distinguish that from a surviving supervisor). Exact pass/fail rule: run `agentchute status` twice, ≥15 seconds apart (three poll ticks). PASS = no old-protocol row's last-seen time advanced between the samples AND no `state/<id>/serve.claim` exists that predates the invalidation (fenced supervisors never re-acquire — reclaim happens only at process start). FAIL (some old row's last-seen advanced) = that supervisor never got fenced (setup died before its reset step): re-run `agentchute setup --yes`, re-verify, or close the pane by hand. Fenced supervisors print the C15 restart notice, SIGTERM their wrapper, exit.
4. **Relaunch lanes** via `ac serve <wrapper>` — now the new binary: acquires a fresh lease, registers (rows recreated with `v: 3`), heartbeats.
5. **Old mail**: all old-format files and crash residue stay fully readable (B6 dual-read); all old-keyed obligations stay dischargeable; old refs keep matching. `check` shows age banners on the stale backlog.
6. **Mixed-version hazard, stated honestly**: an OLD binary receiving NEW-format mail would quarantine it (its lister only knows seq names) — and pre-A6 binaries would also auto-send correctives about it. This is why the cutover is pool-at-once: lease invalidation (step 2/3) makes old binaries stop being able to send or heartbeat within seconds, so the mixed window is bounded by relaunch time, not negotiation. Do not run mixed pools deliberately; `doctor` warns on mixed `v:` values (C27).
7. **Old state left behind** (harmless, cleaned lazily or by hand): `state/<from>/seq/*.json` counter files (dead — nothing reads them; delete opportunistically via `agentchute clean` extension or leave), `live/` dir, `poller.json`/`session.json` (wipe/reset paths no longer recreate them).
8. **Rollback stance**: rollback = reinstall the previous release binary + `agentchute setup`. Caveats, recorded: (a) new-format inbox files are INVISIBLE-then-quarantined to the old binary — drain inboxes (`check` + `turn-end`/`ack` on the new binary) BEFORE rolling back, or accept quarantine + hand-restore from `malformed/`; (b) new registration rows parse fine under the old binary (superset fields absent, `v: 3` warns in doctor); (c) floor files are ignored by the old binary; the seq counters it resumes from are still on disk and monotonic, so old-format sends resume safely. Rollback is a real option through the whole window — that is why B7 does NOT delete old counter files on upgrade.
9. **Post-cutover watch**: `agentchute doctor` clean; `status` shows fresh ages; first sweep observed in serve logs after ~10min; certification/dogfood window per repo convention before the tag is called final.
