# agentchute v1.7.1

One fix, for anyone installing agentchute on a new machine.

**Upgrading.** Nothing else changes: protocol v2.5, registration wire version `v: 3` and hub wire version 1 are the same as v1.7.0. Run `agentchute update` (or `agentchute setup`) once, then open a new shell.

## `agentchute` is found after setup

`install.sh` puts the binary in `~/.local/bin` and, when that directory is not on your PATH, adds a small PATH entry for it to your shell profile. `agentchute setup` then replaced that entry with its own block, and its block named only `~/.agentchute/bin`, where `ac` lives. In a new shell `ac` worked but `agentchute` was "command not found", so the README's `agentchute doctor` failed, and an agent started with `ac serve` could not run `agentchute check` or `send` by name.

Setup's PATH block now carries the agentchute binary's own directory too, the same one `ac` runs. Each directory is added only when it is not already on PATH, for POSIX shells and fish alike, and a second `setup` leaves the profile unchanged ([#232](https://github.com/agentchute/agentchute/pull/232)).

If you already ran setup on v1.7.0 or older and hit this, `agentchute update` fixes your profile. Until then, use the full path, for example `~/.local/bin/agentchute update`.
