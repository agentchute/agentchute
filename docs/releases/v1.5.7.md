# agentchute v1.5.7

This patch release closes two ways a lane could go quiet or act on stale mail: a guard-latched lane can now send a real multi-line reply, and the wake cue says how old the mail is instead of leaving the reader to work it out. Protocol v2.5 and registration wire version `v: 3` are unchanged.

- `agentchute send --body-file <path>` reads the body verbatim from a file the binary opens itself. While the §15 guard latch is held the inert-direct-send exception allows only a single-line `--body "literal"`, and every other multi-line body form (`< file`, a pipe, `--body "$(cat file)"`) is executable shell syntax and is denied — so a lane that had just claimed mail could not send a real reply that turn, parked it "for next turn", and never got one, because a pull-only bus never wakes an empty inbox. Mutually exclusive with `--body` by flag presence, never falls through to stdin, and errors on a missing, unreadable, or directory path before any preflight or delivery. `guard.go` is unchanged ([#141](https://github.com/agentchute/agentchute/pull/141)).
- `--body-file` refuses a path resolving inside the loop's `state/` tree, which holds the live serve token in `state/<id>/serve.claim`; containment is decided by directory identity rather than by comparing path strings, so a case-insensitive filesystem cannot open `STATE/<id>/serve.claim` past a case-sensitive compare. `inbox/`, `archive/`, and `agents/` stay readable, being wire-protocol-public to every peer. This is a bound on an obvious foot-gun, not a security boundary ([#141](https://github.com/agentchute/agentchute/pull/141)).
- The wake cue carries a compact age (`45m`, `31h`, `3d`) on every entry, and a `[stale]` marker on the entries past the threshold, in text, `--json`, and hook-context output, and defaults its staleness threshold to `check`'s existing 24h instead of applying one only when `--stale-after` was passed — which no installed hook template does. A lane read a 31-hour-old message off the cue as a live instruction and broadcast a false alarm to the fleet ([#140](https://github.com/agentchute/agentchute/pull/140)).
- `check`'s old-mail banner names the sender and states the norm; hour-scale mail renders in hours instead of "this message is 1 days old" ([#140](https://github.com/agentchute/agentchute/pull/140)).
- Enrollment prose moved to marker v30 (the latched-reply guidance sits inside the marked block). A normal `agentchute update` re-execs `setup` for the control repo it runs in, using that repo's saved settings, so that repo is re-stamped with no follow-up. Run `agentchute setup --wake runner --wrappers all --yes` yourself in any other control repo, and in any repo where you passed `--no-resync` or the resync failed — until then the binary is current but the tracked wrapper instructions still teach the old guidance.
