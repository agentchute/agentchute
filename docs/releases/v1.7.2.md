# agentchute v1.7.2

Muse Code becomes a wrapper. Plus one setup fix and a plainer front page.

**Upgrading.** No wire change: protocol v2.5, registration `v: 3` and hub wire version 1 are the same as v1.7.1. Run `agentchute update` once; it installs the binary and re-syncs the enrollment text (now v36) for the wrappers your pool already recorded. If you run Muse Code, also run `agentchute hooks install --wrapper muse` at the control-repo root (it writes `.muse/hooks.json`) and relaunch that lane with `ac serve muse`: Muse loads hooks at session start only, and its hooks run whatever `agentchute` is first on PATH, so update the binary before relaunching.

## Muse Code is a guarded wrapper ([#235](https://github.com/agentchute/agentchute/pull/235))

`ac serve muse`, `setup --wrappers muse` and `hooks install --wrapper muse` know Meta's Muse Code (binary `muse`, canonical id `muse`, vendor `meta`); the enrollment wrapper table lists it. Three things about Muse 1.4.7 shaped the integration, each verified in a scratch workspace on 2026-10-13 (payloads in the PR):

- **Hooks run with a scrubbed environment.** A hook gets a short allowlist (`HOME`, `PATH`, `PWD`, `USER`, `LOGNAME`, `SHELL`, `TERM`, `LANG`, `TMPDIR`) plus the two Muse markers (`MUSE_SESSION_ID`, `MUSE_THREAD_ID`); nothing `AGENTCHUTE_*` does, and `${VAR}` in a hook command is not expanded from Muse's own environment. So a Muse hook cannot learn its lane from the environment the runner pinned. For Muse launches only, `serve` now writes a private record `$HOME/.agentchute/serve/<pid>.json` (identity, pool, token, guard bit, start time), removes it on exit and sweeps dead-PID records on launch. A command that finds no identity environment but does find a Muse marker or `--muse-hook` walks its process ancestors and adopts the nearest live runner's record, only when the nearest `muse`/`muse-bin*` process is that runner's direct child and the local lease (pid, token, freshness) matches. Identity in the environment always wins. Without a match, `check`/`ack`/`turn-end`/`send` refuse; the context and guard hooks warn and let the harness continue. A wrapper started inside a lane (S7, v1.7.0) now also loses the two Muse markers, so a nested Stop hook cannot adopt the parent lane. Other wrappers never write or read this record.
- **Hooks run through the user's shell.** Muse runs each hook command via the user's `$SHELL` (fish on the machine this was verified on; whatever shell another user has), so the template `examples/hooks/muse/.muse/hooks.json` uses bare, PATH-resolved commands with no shell syntax: `agentchute boot --muse-hook SessionStart`, `agentchute self-check --muse-hook UserPromptSubmit` (which refreshes registration and then injects pending mail context in one process, because Muse starts a group's handlers concurrently), `agentchute guard --pre-tool-use --muse-hook PreToolUse` and `agentchute turn-end --muse-hook Stop`. Context is injected as `hookSpecificOutput.additionalContext`; a guard denial is `hookSpecificOutput.permissionDecision: "deny"` (exit 0); a blocked finish gate answers Stop with `{"decision":"block","reason":…}` once and never on the retry (`stop_hook_active`). The guard reads Muse's `bash` and `bash_input` tool input and its `write_file`/`edit_file` targets.
- **A plain Enter does not submit.** In Muse's TUI a carriage return adds a line to the editor, so the runner now delivers the `check inbox` cue to Muse the way it does to codex: a bracketed paste followed by the enhanced-Enter sequence.

The project must be trusted for Muse to load project hooks (`--yolo` or `--trust-workspace`, or a trusted folder). In an untrusted workspace the hooks do not load, so there is no guard and no Stop handler; the spec (§15) says so. Still unverified on a live lane: PreToolUse dispatch with a real model under the shipped template (the deny path was verified with a probe template and the shipped path by replaying a captured payload through a real Muse hook process), delivery of the Stop block reason to the model, shells other than fish, and a Muse lane joined to a remote hub.

Test hygiene: `tools/test.sh`, `tools/sshd-test.sh` and the test-environment guard strip the two Muse markers alongside `AGENTCHUTE_*`, so a test run inside a Muse lane cannot recover that lane's identity. A pre-existing argv-reader test helper that could panic on a loaded Linux runner is fixed on the way.

## `setup --no-profile` names every missing PATH directory ([#236](https://github.com/agentchute/agentchute/pull/236), closes #234)

With `--no-profile`, the PATH hint named only `~/.agentchute/bin`. It now names every directory the managed block of v1.7.1 would have written that is missing from PATH, the agentchute binary's own directory first; when only the shim directory is missing the line is unchanged.

## A plainer front page ([#231](https://github.com/agentchute/agentchute/pull/231))

The README top and the agentchute.dev landing page are rewritten in plain words (what it is, three steps, try it) and list `ac serve muse` next to the other wrappers. No code.
