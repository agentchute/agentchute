# agentchute v1.7.3

Three small fixes from the first live run of v1.7.2 across a five-lane pool (2026-10-13). Hotfix; no wire change.

**Upgrading.** Protocol v2.5, registration `v: 3` and hub wire version 1 are unchanged from v1.7.2, and so is the enrollment text (v36). Run `agentchute update` once and relaunch your lanes; nothing else to do.

## `doctor` no longer warns every lane about a codex daemon that cannot host it ([#239](https://github.com/agentchute/agentchute/pull/239))

On a host with several pools, `codex_daemon_env` printed a WARN on every lane of every pool as long as any managed `codex app-server` daemon from some other pool was alive, and its text claimed every codex session on the host ran under that daemon. A lane whose codex child runs `--no-daemon` (what `ac serve codex` has launched since v1.7.0) never touches the daemon: its sends do not fence and its hooks run under its own environment.

The check now reads the lane's serve child from the process table the way `codex_memories` does. A codex child with `--no-daemon` as its own word (scanning stops at `--`) reports OK and still lists the foreign daemon with its pool; a serve child that is not codex is skipped, because the daemon cannot host that lane's hooks; a codex child launched without `--no-daemon`, or a lane whose serve process cannot be found, keeps the previous token/repo verdict. Both the WARN and the OK text now say "codex sessions launched without --no-daemon". Verified live on the pool that found it: the codex lane reports OK, the other four lanes skip.

## `boot`'s inherited-mail note measures against this serve's start ([#238](https://github.com/agentchute/agentchute/pull/238))

`boot` printed "inbox contains mail from before this registration — a previous <id> may have existed" whenever an unread message was older than the registration's `last_seen`, which boot itself had just refreshed. On a wrapper whose session-start hook runs at the first cue (codex, Muse Code) that is every ordinary message, and both lanes reported the note as an anomaly on their first v1.7.2 turn.

The cutoff is now the lane's `serve.claim` `started_at`, which every serve launch or reclaim sets and heartbeats never move: mail older than this serve was addressed to a previous incarnation and still gets the note, now worded "from before this serve started". A lane without a local serve.claim gets no note at all: a hand-run session that never ran `ac serve`, and every hub lane, whose lease is held on the hub rather than in the local state directory. The note is advisory and nothing branches on it.

## `.muse/` and `.agents/` are ignored in the agentchute repo itself ([#238](https://github.com/agentchute/agentchute/pull/238))

`hooks install --wrapper muse` writes `.muse/hooks.json` into the control repo, and `--wrapper agy` writes `.agents/hooks.json`; this repo's `.gitignore` now ignores both directories like `/.codex/` and `/.gemini/`. `init` has never written hook-directory ignores and still does not; this is the project's own ignore file, not a binary change.

## Known limitations

- The PreToolUse guard still denies a read-only command that merely names a hook config path while mail is claimed (three lanes hit it in the live test). The guard is best-effort text matching by design (§15); use a file-read tool instead of `cat` while latched.
