# agentchute v1.7.0

The 2026-10-08 review release. Nothing in it changes the protocol, but a lot changes how a lane meets its mail and how a remote machine meets its hub. Mail is now consumed only by the lane that owns it. `check` no longer archives mail the model never saw, and a peer can no longer pass a forged message off as someone else's. Antigravity (`agy`) is its own wrapper, Gemini CLI commits at the end of its turn, and codex lanes launch without codex's shared daemon and without its memory agent. The SSH hub gains terminal gates for taking over or re-keying a lane, host-key seeding, and a session that releases its lease when the connection goes. A minor version, not a patch: there is a new wrapper, new hook contracts, new hub flags and new codex launch flags.

> **DRAFT.** Two sections are placeholders until their PRs merge: Claude hardening ([#226](https://github.com/agentchute/agentchute/pull/226)) and the S6 / S7 / doctor fixes (fable-medium's PR). The date is set at tag time.

**Upgrading.** Protocol v2.5, registration wire version `v: 3` and hub wire version 1 are unchanged. The hub wire changes are additive. `check` and `ack` frames may carry `serve_token`, `check` frames may carry `budget_bytes`, and the hub may return one new code, `E_SENDER_MISMATCH`. An older peer ignores the new keys. The cutover:

1. **Upgrade the hub first**, as always, then every joined machine. Upgrade a joined machine before running `hub join --rotate-key` against an upgraded hub. The hub now refuses a different-key `--replace-key` without a terminal, and a v1.6.2 client sends none. Its fallback then records an empty pool id, and the lane fails with `E_POOL_MISMATCH` until the authorize command is run on the hub and the join is re-run.
2. **Run `agentchute update`** (or `agentchute setup`) once per control repo. The enrollment marker moves to **v35**, and setup rewrites every wrapper file's enrollment block. The recorded wrapper list is replayed, so a repo that uses Antigravity must add it explicitly: `agentchute setup --wrappers agy`.
3. **Relaunch every lane.** Several changes take effect only at launch:
   - codex lanes start with `--no-daemon` and `--disable memories`.
   - grok lanes start with `GROK_CLAUDE_HOOKS_ENABLED=0`.
   - The guard is armed from the binary actually launched.
4. **PLACEHOLDER (#226):** `serve` refuses to launch on hook-file drift until `setup` has run. Confirm the final behaviour and command from the merged PR.

Also worth knowing before the first turn:
- `ac serve gemini` no longer launches Antigravity. On a host with only `agy`, it fails; use `ac serve agy`. The roster id is then `agy` unless you pass `--as`.
- `check`'s output format changed. Each body sits inside a nonce frame with every line prefixed `│ `, so a script that parses `check` output must adapt.
- `check` claims about 12 KiB per call, and the runner re-cues while mail remains.
- `check`, `ack` and `turn-end` run by hand from another shell are now refused while the lane's serve is live.
- A codex lane must be launched from inside its control repo: bus commands from a codex thread whose working directory is outside it are denied.

## Mail is consumed only by the lane that owns it

- **The consume path is fenced.** While a fresh serve claim owns an id, `check`, `ack` and `turn-end`'s archive step refuse a process with a different serve token (`E_FENCED`), and one with no token at all (`E_LEASE_HELD`). Before this, a process on a stale or foreign env could claim a live lane's mail, show it to the wrong agent and archive it. The check repeats under the agent lock before every claim, archive and quarantine. `check --no-archive` stays a read-only peek, and a stale or missing claim changes nothing. The hub applies the same rule to `check`/`ack` frames that carry `serve_token`; a frame without it is served as before, unfenced ([#211](https://github.com/agentchute/agentchute/pull/211)).
- **A runner env from outside its process tree is refused.** When `AGENTCHUTE_RUNNER_PID` is set, `check`, `ack`, `turn-end`, `send` and `boot` refuse unless that runner is this process or an ancestor. `guard`, `pending` and `self-check` only warn. This is the class behind codex's shared daemon running hooks with the first lane's env. Lookups use `sysctl` on macOS and `/proc` on Linux; other platforms skip the check ([#211](https://github.com/agentchute/agentchute/pull/211), [#215](https://github.com/agentchute/agentchute/pull/215)).

## `check` shows what it archives, and frames what it shows

- **Byte-budgeted claims.** `check` stops claiming before a message that would push its output past 12 KiB (`--budget-bytes` overrides; `0` lifts it), always takes at least one new message, and says how many are still pending. Every harness truncates tool output, so a large inbox could be archived by `turn-end` with most of it never shown to the model ([#212](https://github.com/agentchute/agentchute/pull/212)).
- **One bad file no longer wedges an inbox.** An inbox file over 4 MiB, or one that cannot be read, is quarantined to `malformed/` with a warning, and the claim goes on. `send` refuses a body over 4 MiB minus 4 KiB of envelope room, for `--body`, `--body-file` and stdin alike ([#212](https://github.com/agentchute/agentchute/pull/212)).
- **A peer cannot forge the sender.** `send` (local and on the hub) refuses content whose frontmatter `from` names someone other than the sender, with `E_SENDER_MISMATCH`. `check` prints every body between `---- <file> [frame <nonce>] ----` and `==== end of <file> [frame <nonce>] ====`, with a fresh nonce per run and each body line prefixed `│ `. A fake header inside a body is therefore visibly part of that message. The real reply hint prints outside the frame, and a frontmatter `from` that disagrees with the filename gets a one-line `[!] SENDER MISMATCH` warning ([#215](https://github.com/agentchute/agentchute/pull/215)).

## Wrappers: agy, Gemini CLI, codex, grok

- **Antigravity (`agy`) is its own wrapper**: `ac serve agy`, `setup --wrappers agy` and `hooks install --wrapper agy`, with a template installed at `.agents/hooks.json`. It uses `PreInvocation` for context (first invocation only), a `PreToolUse` guard that answers `ask` or `deny`, and a `Stop` commit that answers `stop` or `continue`. `agy` is no longer a gemini candidate, so `ac serve gemini` cannot silently launch it ([#214](https://github.com/agentchute/agentchute/pull/214)).
- **Gemini CLI commits at the end of its turn.** The commit moves from `BeforeAgent` (the next prompt) to `AfterAgent`. It is silent when clear, and when blocked it denies with a reason, so Gemini retries once; it never denies its own retry. `BeforeAgent` now runs `self-check` and `pending`, and context goes out through `additionalContext` ([#214](https://github.com/agentchute/agentchute/pull/214)).
- **codex launches without the shared daemon and without memories.** When the installed codex advertises the flags, `serve` adds `--no-daemon` and `--disable memories` right after the program name. Neither is added twice, or when you already chose, or for `queue`, `agents` or `--remote`. codex 0.161's shared daemon ran every lane's hooks with the first lane's env. Its memory agent ran inside a lane and once sent a message that lane never wrote. To keep memories, launch with `ac serve codex --enable memories`. Two new `doctor` checks, `codex_daemon_env` and `codex_memories`, report a daemon carrying another lane's env and a lane with memories on ([#210](https://github.com/agentchute/agentchute/pull/210), [#217](https://github.com/agentchute/agentchute/pull/217)).
- **codex threads outside the control repo cannot run bus commands.** For a codex tool call whose working directory is outside the control repo, the guard denies `send`, `check`, `ack`, `turn-end`, `clean`, `setup` and `update`, latched or not. The lane's lifecycle hooks do nothing for such a thread ([#217](https://github.com/agentchute/agentchute/pull/217)).
- **codex hook trust is checked before arming the guard.** codex trusts each hook by its position and hash. `serve` launches a local codex lane UNGUARDED, with a warning, when any expected trust entry is missing or stale, instead of arming a latch that a skipped hook would never clear. Such a lane runs `ack` itself, as the warning says ([#213](https://github.com/agentchute/agentchute/pull/213)).
- **grok is actually hookless under `serve`.** grok 1.0.46 scanned the repo's Claude Code hook file by default and ran claude-code's Stop hook unguarded. `serve` now launches it with `GROK_CLAUDE_HOOKS_ENABLED=0` ([#213](https://github.com/agentchute/agentchute/pull/213)).
- **The guard reads a codex `apply_patch` by its target files only**, so a doc patch that mentions a denied word is allowed, and a patch that targets a hook file is still denied ([#213](https://github.com/agentchute/agentchute/pull/213)).

## The SSH hub

- **Taking over or re-keying a lane needs a terminal.** `hub authorize` refuses to bind a key to an id the pool already knows (registration row, fresh claim, inbox or lane state) unless `--takeover` is given with a real terminal on stdin. A `--replace-key` with a different key needs the same. `hub join --rotate-key` passes `ssh -t` when run from a terminal; otherwise it prints the authorize command and keeps the old key and pool identity working. A terminal is not proof of a human ([#216](https://github.com/agentchute/agentchute/pull/216), [#218](https://github.com/agentchute/agentchute/pull/218)).
- **Joining no longer starts from blind trust.** Before the first connection, `hub join` copies the user's and the system's existing `known_hosts` entries for the hub, under the name ssh actually checks (its `HostKeyAlias`, `HostName` and `Port`, from `ssh -G`), and refuses if `ssh -G` fails. A migration to a new URL proves "same hub" with a probe pinned to the old hub's key (strict checking, `@revoked` honoured), and agentchute no longer runs `ssh-keyscan`. `--replace` is needed to point a checkout at a different hub ([#216](https://github.com/agentchute/agentchute/pull/216)).
- **Smaller hardening.**
  - A joining URL's pool path must be `[A-Za-z0-9._/+-]+`, and every printed "run this ON THE HUB" command single-quotes its arguments.
  - The `/tmp/ac-<uid>/` socket parent is ownership-checked.
  - Agent and X11 forwarding are off on every hub ssh.
  - Any failure after a send is on the wire is `E_SEND_UNKNOWN`.
  - ssh's stderr is kept as a 64 KiB tail ([#216](https://github.com/agentchute/agentchute/pull/216)).
- **The guard stops the hub commands while mail is claimed.** `hub authorize`, `hub join` and `hub session` are denied when they are run, not when they are mentioned. The rule models ordinary shell words, common wrappers, nested `sh -c`/`eval`/ssh commands, and a shell reading from stdin. Command text over the guard's 4 MiB work budget is refused in constant time once it reaches the guard ([#216](https://github.com/agentchute/agentchute/pull/216), [#220](https://github.com/agentchute/agentchute/pull/220), [#225](https://github.com/agentchute/agentchute/pull/225)).
- **A hub session gives its lease back when the connection goes.**
  - A broken stdout no longer kills `hub session` before it releases the lease. A Go program that has not asked for SIGPIPE dies on a write to a closed pipe, so a reply already in flight when the client vanished left the claim behind ([#221](https://github.com/agentchute/agentchute/pull/221)).
  - A SIGHUP or SIGTERM now ends the session even while sshd's pipes stay open: at once when it is waiting to read, and after a 250 ms grace when it is stuck writing. Before, it waited up to 20 s (blocked read) or 30 s (blocked write) ([#224](https://github.com/agentchute/agentchute/pull/224)).
  - Either way, a relaunching remote lane could meet `E_LEASE_HELD` and stop.

## Known limitations

- **The guard is best-effort.** It is a bounded model of shell syntax, not an interpreter. Arbitrary variables, aliases, script files, general expansion and dialect syntax are not resolved. The wrapper utilities it does not model (`caffeinate`, `script`, `flock`, `setsid`, `arch`, `sandbox-exec`, `watch`, `unbuffer`) can get a hub command past it (AGENTCHUTE.md §15).
- **PLACEHOLDER (#226) — the guard hook's input limit.** On main the hook reads at most 1 MiB of its input, and a larger tool call fails to parse and is allowed. #226 raises the read to 32 MiB and denies an oversized input while latched. Replace this line with the merged behaviour; drop it if nothing is left open.
- **The hub fences only clients that send their token.** A `check`/`ack` frame without `serve_token` is served unfenced, which keeps older clients working (tracked in [#227](https://github.com/agentchute/agentchute/issues/227)).
- **The terminal check is not authentication.** `ssh -t`, `script`, `expect` or any tool that runs commands in a pseudo-terminal passes it. On platforms other than macOS and Linux, the check always refuses.
- **Gemini CLI and Antigravity are not live-verified.** Their hook shapes follow vendor docs. Gemini retries once on a blocked end-of-turn. **agy's `Stop` has no retry cap**: a gate that stays blocked answers `continue` every time.
- **codex's foreign-thread rule keys on the working directory** ([#222](https://github.com/agentchute/agentchute/issues/222)). With a pool at `$HOME`, the memory thread runs inside the control repo, so neither the guard rule nor the hook no-op fires. The fix is to key on codex's `session_id`.
- **PLACEHOLDER (fable-medium's PR) — codex hook trust for `ssh://` lanes.** On main the trust check is skipped for remote lanes, so a remote codex lane arms the guard without it. Replace with the merged behaviour.
- **Host-key seeding reads only the default files** (`~/.ssh/known_hosts`, `/etc/ssh/ssh_known_hosts`), not a custom `UserKnownHostsFile`. With nothing found, the first connection is still accept-new. A migration to a URL that already has a matching hub config reuses it without the pinned probe (both tracked in [#227](https://github.com/agentchute/agentchute/issues/227)).
