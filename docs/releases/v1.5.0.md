# agentchute v1.5.0

Protocol v2.5 deliberately changes the wire identity while retaining the pull-only primitives, small envelope, and two-phase recipient lifecycle.

Highlights:

- Timestamp-plus-random-suffix message identities replace the shared sequence allocator.
- Delivery is explicitly at-most-once; recipient consumption remains at-least-once.
- Registration rows are soft state and the sole presence source.
- Agent identity is explicit; contextual folder guessing is removed.
- One frontmatter parser now serves registrations and message envelopes.
- The guard is documented as best-effort defense-in-depth, never a security boundary, with vendor and launch-mode gaps named.
- The complete release range removes 8,617 lines, measured with `git diff --numstat v1.0.0..v1.5.0` rather than copied from the plan.

This is a pool-at-once migration. On the first old→v2.5 upgrade, fencing happens only when the old updater re-executes the new binary's setup reset. Do not use `--no-resync`. Freeze sends, update once, verify fencing with two `status` samples at least 15 seconds apart, then relaunch every lane.

Read and execute the full [Protocol v2.5 live-pool cutover checklist](https://github.com/agentchute/agentchute/blob/v1.5.0/docs/V2_5_CUTOVER.md), including rollback caveats, before resuming sends.

Release artifacts are built once, installed through the real `install.sh` from a staged `file://` release base, checked for version, clean fixture-pool diagnostics, checksums, and `vcs.modified=false`, then published without a rebuild.
