# agentchute v1.5.5

This patch release fixes one guard denial: a latched lane following the enrollment docs' own identity spelling could not send at all. Protocol v2.5 and registration wire version `v: 3` are unchanged.

- The guard's direct-send exception now tolerates `$AGENTCHUTE_AGENT_ID` / `${AGENTCHUTE_AGENT_ID}` — the spelling the enrollment docs mandate on every command — so a guard-latched lane can reply without rewriting its identity flag to a literal. Every other parameter expansion (`AGENTCHUTE_SERVE_TOKEN` above all), longer variable names sharing the prefix, command substitution, redirection, and compound shell syntax still deny the exception ([#136](https://github.com/agentchute/agentchute/pull/136)).
